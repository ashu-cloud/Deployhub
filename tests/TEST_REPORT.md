## Fixes applied (previously 22 failures)

### P0 — fixed before any real traffic

| Finding | Fix |
|---|---|
| `dev-bypass` / `dev-token` / `mock-dev-token` accepted as a real identity with no signature | Removed entirely from `get_current_user`; only real signed JWTs are accepted |
| Frontend login page shipped a "Dev Bypass" button that wrote the fake token | Removed the button and its handler from `frontend/src/app/login/page.tsx` |
| `git clone` used `create_subprocess_shell`, interpolating `repo_url`/`branch` into a shell string | Switched to `create_subprocess_exec` with an argv list + strict allow-list validation (`_validate_clone_inputs`) in `build-orchestrator` |
| `GET /deployments/{project_id}`, detail, and rollback had no auth dependency | Added `get_current_user` to all deployment-service HTTP routes |
| Build-log WebSocket accepted connections with no auth | Added token-via-query-param validation (`get_current_user_from_token`) before accepting the socket |
| `docker-compose.yml` inlined a Groq-style API key | Replaced with `${GROQ_API_KEY:-}` sourced from `secrets/compose.env` |
| Caddy admin API bound to `0.0.0.0:2019` | Moved to a Unix socket shared only with `deployment-service` via a Docker volume; `:2019` is never published |

### P1 — secrets, crypto, and request surface

| Finding | Fix |
|---|---|
| Shared default `JWT_SECRET_KEY` (HS256) in code | Migrated to RS256: `auth-service` holds a generated private key and signs; every other service verifies with the public key only. No key material is hardcoded or committed (`scripts/generate_secrets.py`, gitignored `secrets/`) |
| Default `WEBHOOK_SECRET` hardcoded | Now a required env var with no default; fails closed if unset |
| `ENV_VAR_ENCRYPTION_KEY` was 16 bytes (AES-128) | Required 32-byte (64 hex char) key, validated at startup; `EncryptionService.__init__` raises if missing/wrong length |
| JWT algorithm was HS256; architecture called for RS256 | Implemented (see above); added `refresh_token_cannot_be_used_as_access_token` regression test |
| OAuth callback only returned the access token, no distinct refresh token | Auth service now issues both: access token in the JSON body (held in memory client-side), refresh token in an HttpOnly+Secure+SameSite=Strict cookie; added `/auth/refresh` and `/auth/logout` |
| Auth CORS was `allow_origins=["*"]` + `allow_credentials=True` | Explicit `CORS_ORIGINS` allow-list (defaults to the frontend origin only) |
| Project-service CORS was also `*` | Same explicit allow-list fix |
| MinIO bucket policy granted `s3:GetObject` to `Principal: *` over the whole bucket | Scoped the public grant to the `deployments/*` prefix only (public static-site hosting is intended; the rest of the bucket is not) |
| ~200 KB JSON to `POST /projects/` returned 500 | Added `Field(min_length=..., max_length=...)` constraints on `ProjectCreate`/`EnvVarCreate`; oversized payloads now get a clean 422 |
| 40-POST burst produced no 429; connection dropped | Added a Redis-backed fixed-window rate limiter (`rate_limit_create_project`, default 10 req/10s per user) — verified with a dedicated regression test |

## Bugs found and fixed during live verification (not in the original static audit)

These surfaced only once the rebuilt stack was actually exercised end-to-end:

| Bug | Fix |
|---|---|
| `upload-service` used env var `S3_ENDPOINT` but the setting field is `S3_ENDPOINT_URL` — service silently fell back to `localhost:9000` and crashed on startup inside the container | Fixed the compose env var name to match `S3_ENDPOINT_URL` |
| GitHub webhook registration always sent `Authorization: Bearer ` (empty) when no `GITHUB_API_TOKEN` was configured — httpx raises `LocalProtocolError` on an illegal header value, which crashed the whole `create_project` request/connection | Only send the `Authorization` header when a token is configured; wrapped the GitHub API call in `try/except httpx.HTTPError` so it degrades to the existing MVP fallback instead of taking down the request |
| Webhook delivery-id idempotency was a check-then-act race (`GET` then `SETEX` at the very end) — a parallel replay of the same `X-GitHub-Delivery` queued **16 duplicate builds** instead of 1 | Replaced with an atomic `SET NX EX` claim up front; releases the claim on downstream failure so a legitimate GitHub retry isn't permanently swallowed |
| A stray root `.env` (from the first secrets-generation pass) broke every service's `pydantic-settings` with `extra_forbidden`, since each service's `Settings` model only defines its own keys | Secrets now write to `secrets/compose.env`, passed explicitly via `docker-compose --env-file secrets/compose.env`, never auto-loaded by any service |
| Fresh Postgres/MinIO volumes with rotated passwords | Recreated `postgres_data`/`minio_data` volumes so the DB/object-store auth matches the newly generated secrets |
| `test_no_eval_or_pickle_in_services` false-positived on `asyncio.create_subprocess_exec(` (substring `"exec("`) | Switched the banned-token scan to word-boundary regexes |
